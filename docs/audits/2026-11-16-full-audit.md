## Находки и ТЗ — по ходу пользовательского сценария

### A4 · P1 · «Остановить» перестаёт работать после обхода дерева

**Место:** `src/main/index.ts:164–181`, `:220–239`.

**Воспроизведение:** запустить страницу с инстансом; отправить
`ui/scan-cancelled` во время `getMainComponentAsync`. Проверка A4 отправляет
сообщение прямо из замоканного async-резолвера мастера.

**Получено:** `report.cancelled === false`, в `trend.points` записан снимок.
Флаг отмены проверяется только в traversal; гидрация переменных и цикл
мастеров его не читают. Пользователь продолжает ждать все async-вызовы,
затем видит обычный завершённый отчёт. На этой фазе прогресс также не обновляется.

**Исправить:** проверять отмену между async-вызовами всех фаз; не запускать
следующие запросы после отмены, вернуть частичный отчёт и не сохранять снимок.
Текущий незавершённый запрос можно дождаться, транзакционная отмена API не нужна.

**Приёмка:** отмена во время гидрации и во время резолва мастеров даёт
`cancelled: true`, не запускает оставшиеся запросы и не меняет историю.
UI показывает неполный результат; текст «Первый замер сохранён» не показывается
для несохранённого частичного отчёта.

### A1 · P1 · Недоступные переменные считаются библиотечными токенами

**Место:** `src/main/index.ts:185–196`, `src/main/analysis/usage.ts:88–109`.

**Воспроизведение:** одна нода с биндингом `fills → missing`;
`getVariableByIdAsync('missing')` возвращает `null`.

**Получено:** `nodesOnLibraryVariable === 1`, но `topVariables` пуст.
`resolver.isLocal` возвращает false и для library, и для unavailable;
`splitByLocality` любое false превращает в библиотечное покрытие.

**Последствие в UI:** покрытие токенами растёт за счёт непроверенных зависимостей,
хотя вкладка токенов не может показать эти зависимости. Ошибка попадает в
историю и Markdown-экспорт.

**Исправить:** передавать в расчёт три состояния, вести недоступные отдельно.
Исключить их из подтверждённого библиотечного покрытия и объяснить неполноту.

**Приёмка:** нода только с unavailable не увеличивает библиотечный счётчик;
смесь local/library/unavailable не задваивает ноды, UI и экспорт используют
одинаковые определения.

### A2 · P1 · Привязка размера скрывает хардкод цвета

**Место:** `src/main/index.ts:140–146`, `src/ui/parts/report.tsx:53–56`,
`src/shared/advice.ts:100–111`, `src/main/analysis/snapshot.ts:19–33`.

**Воспроизведение:** прямоугольник с красной SOLID-заливкой без переменной;
только `width` привязан к локальной переменной `spacing`.

**Получено:** `nodesWithoutVariable === 0`, `nodesOnLocalVariable === 1`.
Для этой ноды получается 100% покрытия; совет «Цвета без токенов» отсутствует.
При отсутствии привязки width та же заливка считается нетокенизированной.

**Причина:** любые привязки попадают в числитель, а в знаменатель без привязок
попадают только ноды с заливкой. Наличие width, opacity или другой переменной
не доказывает, что цвет переключается вместе с темой.

**Исправить:** разделить общую статистику привязок и покрытие цвета. Для
цветового покрытия считать соответствующие привязки заливки на одном наборе
нод; для общей метрики определить единый набор кандидатов и убрать выводы
про переключение цветов, которые из неё не следуют.

**Приёмка:** добавление width-токена к raw-fill не меняет покрытие цвета и не
убирает предупреждение. Сводка, история и экспорт считают одну метрику.

### A3 · P1 · История смешивает разные страницы и выделения

**Место:** `src/main/index.ts:216–230`, `src/main/analysis/snapshot.ts:35–60`,
`src/shared/snapshot.ts:12–17`.

**Воспроизведение:** в один день проверить страницу A с библиотечным покрытием
100%, затем страницу B с покрытием 0%. Оба снимка получают `scope: 'страница'`.
Проверка A3 подаёт эти два снимка в `appendSnapshot`.

**Получено:** остаётся только снимок B. При сканировании в разные дни A и B
попадают в один тренд; возникает ложное падение на 100 п.п. То же происходит
с разными выделениями: в снимке нет идентификатора объекта замера.

**Исправить:** хранить идентичность цели отдельно от её подписи: pageId для
страницы, нормализованный набор root id для выделения, отдельный ключ файла.
Схлопывать день и строить тренд по этому ключу; старые снимки без идентичности
не смешивать с новыми точными сериями.

**Приёмка:** A и B в один день сохраняются раздельно; тренд A не содержит B;
повторный замер A в тот же день заменяет только A. Подпись охвата в UI
позволяет понять, какую страницу сравнивают.

### A7 · P1 · Биндинги свойств компонента отсутствуют в impact analysis

**Место:** `src/main/index.ts:104–112`.

**Воспроизведение:** INSTANCE с
`boundVariables.componentProperties = { 'label#1': { type: 'VARIABLE_ALIAS', id: 'label' } }`;
переменная `label` доступна локально.

**Получено:** `topVariables` пуст, `nodesOnLocalVariable === 0`.
`allAliases` поддерживает массивы и отдельные alias, но игнорирует вложенный
словарь `componentProperties`. Формат словаря подтверждён локальным
`@figma/plugin-typings/plugin-api.d.ts:6449–6463`.

**Последствие:** текстовые/булевы зависимости компонента пропадают из списка
мест, на который пользователь полагается перед изменением токена.

**Исправить:** явно собирать alias из componentProperties вместе с остальными
поддерживаемыми полями. Использовать существующую дедупликацию nodeId/variableId.

**Приёмка:** текстовая и булева переменные свойств видны в impact analysis;
один id в нескольких свойствах одной ноды считается один раз.

### A5 · P1 · Поиск не находит используемые токены за пределами первых 60

**Место:** `src/main/index.ts:28`, `:191–196`,
`src/main/analysis/usage.ts:117–139`, `src/ui/parts/report.tsx`, `VariablesTable`.

**Воспроизведение:** добавить в индекс 61 разный токен на 61 ноде с одинаковым
числом использований. Передать UI результат `usage.describe(resolve, 60)`.
Найти `token-60`, находящийся за срезом.

**Получено:** индекс содержит 61 токен, но в данных UI token-60 отсутствует;
локальный поиск возвращает «Ничего не нашлось». Загрузить следующую порцию нельзя.

**Последствие:** пользователь не может проверить менее популярную зависимость
перед её изменением и получает ложный ответ об отсутствии результата.

**Исправить:** выполнять поиск по полному индексу в main и выдавать результаты
порциями либо передавать весь доступный для поиска каталог. Отдельный топ-60
может остаться в сводке, но не должен ограничивать глобальный поиск.

**Приёмка:** поиск находит 61-й и более поздние токены; пагинация и общее
количество результатов явные. Сохранить ограничение размера сообщений.

## Что проверено и что не доказано

- `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` — прошли.
  Штатно: **156 тестов / 18 файлов**. UI: **409,6 / 500 КБ**, main: 17,3 КБ.
- Дополнительно выполнены **7 проверок воспроизведения**: A1–A5, A6, A7.
  Все подтвердили описанное текущее поведение. Это проверки наличия дефектов,
  а не регрессионные тесты исправленной реализации.
- A6: локальная коллекция из 100 неиспользуемых переменных возвращает 100 в
  `collectionsWithUsage`, библиотечные коллекции собираются из встреченных
  привязок. Счётчики имеют разный охват. **Не включено в P1**: интерфейс не
  обещает явно, что это только использованные токены; требуется определить
  смысл показателя и подписать его, затем согласовать подсчёт.
- По runtime-исходникам: сетевой отправки содержимого файла не найдено;
  `networkAccess.allowedDomains` — `none`. HTML иконок — из вендорного JSON,
  пользовательские имена выводятся React-текстом. Это не аудит всей цепочки
  поставки зависимостей и не доказательство безопасности Figma-платформы.
- Реальные API, скорость на 150k нодах, поведение при параллельном редактировании
  документа и запись в боевой файл в этом проходе не проверены.
- Проверка форматирования отслеживаемых файлов отмечает существующий
  `manifest.json`; файл не переформатирован. Незакоммиченный `AGENTS.md`
  сохранён без изменений. Это не P0/P1 и не исправление в рамках аудита.
